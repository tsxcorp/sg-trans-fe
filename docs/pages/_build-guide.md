# Page build guide (read before building or testing any page)

Applies to: About Us, Contact, Our Service (+ Service Detail), News (+ News Article). Specs: `docs/pages/<page>.md`. Intent and stories: `docs/requirements.md` (S5 responsive, S6 navigation, S7 newsletter, S8 cards/carousels, "Actions (M2b)"). Rules: `CLAUDE.md`, `AGENTS.md` (this Next.js 16: read `node_modules/next/dist/docs/01-app` before using an API you are unsure about).

## Roles (never mix)
- **Builder** writes code under its own folders. **Tester** writes tests from the spec files + requirements only and never reads `src/`. **Reviewer** is read-only. A builder never edits tests; if a test looks wrong, say so in the report with evidence.
- Test authors: put new tests in `tests/e2e/<page>.spec.ts`, `tests/contract/<page>.test.ts`, `tests/visual/<page>.spec.ts`, helpers in `tests/helpers/<page>.ts`. Do not edit another page's tests or shared helpers (copy what you need).

## How to build (same loop as Home)
1. Use `PageShell` (`@/components/shell/PageShell`): header (overlays the first section from xl), `<main id="main">`, footer. First section starts at y = 0. Reuse shared sections when the spec says "shared": `Cta` (`@/components/cta/Cta`), `Partners` (`@/components/partners/Partners`, prop `className` overrides its xl absolute position: pass `""` for normal flow), `QuoteCard`/`QuoteForm` as reference only (Contact/Services have their own form components that post to the shared `submitQuote` action with hidden `source` = `contact` or `services`, locale, honeypot `website`; Lead extra fields `service_type`, `estimated_volume`, `message` already exist). `Carousel` (`@/components/ui/Carousel`), `CmsImage` (`@/components/ui/Image`; images by file id uuid via `assetUrl`), icons in `@/components/ui/icons` (add your own icons inside your page folder).
2. Data only through `lib/cms` style functions in your `src/lib/cms/pages/<group>.ts`: Directus-shaped records (`id,status,sort,date_created,date_updated`, `translations[]` keyed by `languages_code`, file ids as uuid), resolved with `resolveRecord` from `@/lib/cms/resolve`, only `status=published`. No text literals in components: strings come from `translations[]` or your page messages file. Export the function names given in your spec (section 3/4) so the tests can import them.
3. Fidelity at 1920 (design export in `design/exports/<page>/desktop-1920@1x.png`, crop to x 4..1923 when the export is 1928 wide: use `scripts` with PAGE set; if the export has a 4 px offset note it in `design/reference/<page>.md`): `PAGE=<page> DEVICE=desktop-1920 node scripts/shot.mjs` then `PAGE=<page> DEVICE=desktop-1920 python3 scripts/cmp.py`, `side.py y0 y1`, `bb.py x0 y0 x1 y1 [tol|white]`, `rects.mjs`. Target <= 3% full-page difference at 1920 and equal page height. Measure first, then build, then diff; fix the biggest regions first. Use the xl pattern of Home: below xl normal flow; from xl (>= 1280) exact px layout in a fixed-width centered container (see `Stats`, `Cta`, `Footer` for the pattern: `xl:` classes). Images: cut from the export with inpainting (see `scripts/extract_fixture_images.py` for the technique) when the original is not available; list each in `design/reference/<page>.md`.
4. Responsive (requirements S5): no horizontal scroll at 320, 360, 375, 428, 600, 768, 900, 1024, 1180, 1280, 1366, 1440, 1536, 1920: check with `node scripts/widths.mjs /en/<route>`. Breakpoints: base = phones (< 768), `md` tablets, `lg` >= 1024, `xl` >= 1280 = the design. Derive mobile/tablet from the Home patterns (carousels with dots, 2-column grids, stacked blocks, tab lists); keep touch targets >= 44 px; text never clipped.
5. Accessibility and actions: one `<h1>`, real landmarks, labels on every control, visible focus (global ring exists), `aria-current`, keyboard operable widgets, no `href="#"`: every link goes to a real route. Routes that do not exist yet (other pages) are fine to link to. Forms: honeypot `website`, server validation, success/error states with focus handling like `QuoteForm`.
6. Verify: `pnpm typecheck && pnpm lint && pnpm test` and `pnpm exec playwright test tests/e2e/<page>.spec.ts tests/visual/<page>.spec.ts` once the tests exist. The dev server runs on :3000 (`pnpm dev`, already started; if it is down start it in the background). If Vitest says "Cannot find native binding": `CI=true pnpm install --force --config.confirmModulesPurge=false`.

## Decisions already taken (defaults; the owner can override later)
1. The active nav item follows the route (the designs draw HOME active on every page: that is a design shortcut).
2. Forms on Contact and Services follow the design fields (Corporate Email = `email`, Service Type, Estimated Volume, Project Brief = `message`; company/country/job title are not shown). The design copy "respond within 4 hours" is NOT shown (earlier decision: no response-time promise): use a neutral sentence in the page messages, flag it in the report.
3. Fonts: Inter only. The geometric display fonts in some blocks of the designs are replaced by Inter (no external fonts): note it as a known difference.
4. Unknown facts (numbers, names, claims, emails cut off in the design): use the design's visible values as sample fixtures; complete truncated values by pattern and mark `sample` in the fixture comment/report. Never invent certifications, clients or prices that are not in the design.
5. Download buttons without a file: render disabled with an accessible explanation, not a dead link.
6. Maps: the static map image links to the maps provider in a new tab (`rel="noopener noreferrer"`); no third-party script or iframe is loaded.
7. News: reproduce the design as drawn (including its double hero), flagged as an anomaly; add sample articles so pagination and filters are testable (mark them sample). Comments, share links and previous/next are not built (the design has none).
8. Service detail template: the example content of the design is the full content for the first service (`logistic-service`); other services use the same template with their own title and the default sample blocks.
9. Privacy Policy and Terms pages are created by the lead (simple pages). Link to `/en/privacy-policy` and `/en/terms`.
10. Mobile and tablet have no pixel gate (only the 1920 gate at <= 3%); they are checked structurally (S5).

## Report format (your final message)
Files created, what is done per acceptance criterion id, measured fidelity numbers (1920 diff % per page, widths check), known differences, shared change requests, open questions, anything you could not verify. Be concise and honest: say "not verified" when you did not run something.
